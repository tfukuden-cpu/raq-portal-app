# 基本職100体 画像生成プロンプト集（SPEC.md §6-7 ②画像フェーズ）

20職業 × 5種族 = 100体を **10シート**で生成する。1シート = **5列(種族) × 2行(職業) = 10体**。
分割スクリプトは ID を**行優先（左上=STARTIDX → 右 → 下）**で `char-{n}.png` に出力するため、
このレイアウトで `charId = (職index-1)*5 + 種族index` にぴったり一致する。

> **画像生成は ChatGPT で行う**（Higgsfield禁止）。chatgpt.com に下記プロンプトを貼り、生成画像をDL →
> `public/rpg/jobs-sheet{N}.png` として保存 → 分割コマンドを実行（既存 char-* を上書き）。

---

## ⚠️ 実行前の必須手順（順序厳守）

新しい基本職は `char-1..100.png` に書き込まれ、**既存のモンスター画像 `char-37..108.png` を上書きしてしまう**。
モンスターはパートナーとして残すので、**先に `mon-1..72.png` へ退避**しておくこと。

```powershell
# 1) モンスター退避（char-37..108 → mon-1..72）
powershell -ExecutionPolicy Bypass -File scripts\rename-monsters-to-mon.ps1
# → public/rpg/mon-1.png .. mon-72.png ができる（元の char-37..108 はこの後の生成で上書きされてOK）
```

退避を確認してから、以下のシート生成に進む。

## 共通スタイル（毎回プロンプト先頭に付ける）

```
16ビットSNES時代のJRPG風ドット絵キャラクター（クロノトリガー／FF6のような上質なスプライト）。
・全身・正面向き・少し頭身を高めにした親しみやすい2.5頭身
・やわらかい笑顔、くっきりした輪郭線、ていねいな陰影とハイライト
・背景は完全な白一色（#FFFFFF・グラデや影を置かない）
・キャラ同士は重ならず均等に配置、周囲に十分な余白
・文字・ラベル・番号・枠線・吹き出しは一切入れない
・レイアウトは 横5体 × 縦2体 = 合計10体のグリッド
```

## 種族（列の並び・左→右で固定）

| 列 | 種族 | 見た目の固定マーカー（どの職業でも共通） |
|----|------|------------------------------------------|
| 1列目 | ヒューマン | 標準体型・ベージュの肌・丸い耳・20代の若々しい顔。最も標準的 |
| 2列目 | エルフ | すらりと高め・長く尖った耳・色白・切れ長の目・金or銀の髪・優雅 |
| 3列目 | ドワーフ | 背が低くがっしり・立派なヒゲ・太い腕・編んだ髪／ヒゲ・無骨 |
| 4列目 | じゅうじん | 獣の耳としっぽ（オオカミ/ネコ系）・毛皮の質感・鋭い犬歯・野性的 |
| 5列目 | りゅうじん | 竜の角と頬／腕の部分的な鱗・縦長の瞳孔・しっぽ・エキゾチック |

> **各行（横一列）は同じ職業**で、武器・装備・役割が分かるシルエットは保つ。
> ただし **10体すべてが別人に見えるよう**、一人ひとり **性別（男女混ぜる）・年齢（若者〜年配）・髪色/髪型・顔立ち・体格・ポーズ・装備の配色** を大きく変える（個体差を出す）。
> 同じ顔・同じ配色のコピーにしない。**職業ごとの色は固定しない**（下のシート別の色指定は目安で、配色は個体ごとにばらす）。
> 種族（列）の違いは一目で分かるよう**はっきり強調**する。

## 生成のコツ

- うまく10体そろわない・職業が混ざる場合は、シートを **5列×1行（1職業ずつ）** に分けて生成してもよい
  （その場合 `COLS="5" ROWS="1"`、STARTIDX は各職業の先頭IDに合わせる: ゆうしゃ=1, せんし=6, …）
- 種族マーカー（耳・角・体格）は毎回プロンプトに明記しないと崩れる。上の種族表をそのまま貼ること
- 分割後は `WARN` 行が出ていないか確認（「too large」「no pixels」が出たら生成し直し）
- 全シート差し替え後、`public/sw.js` の `CACHE_VERSION` を上げる（旧キャッシュ破棄）

## このフェーズの残り（画像が揃ったあと）

1. アバター表示を旧 `RPG_CHARS` → 新 `jobCharIdFor`/`jobCharImg` に切替（My・AppNav・ホーム・打刻端末・休憩室）

4. 連れ歩きパートナーの表示（`active_partner_id`）
5. `sw.js` CACHE_VERSION up
